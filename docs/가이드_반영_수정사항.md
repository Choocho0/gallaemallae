## 1. 앱 설계 원칙 기반 수정 사항

### 1-1. 화면 구조·윈도우 모델 (P0)
가이드: 화면은 Status bar / Driving view / GNB / App window로 구성되고, **Driving view(텔테일·속도·miniTBT)는 고정이며 앱이 가리거나 닫을 수 없음**. Connect-S는 세로 앱 2개(1:1) 또는 가로 앱 1개(2:0)이고, **기본 Primary 앱은 시스템 내비게이션이며 닫을 수 없음**.

| # | 현재 | 수정 |
|---|---|---|
| 1 | 주행 화면 왼쪽 1680px에 자체 지도, 경로, 턴 안내 카드, 속도계, ETA 바를 그림 | 자체 지도, 턴 안내, 속도계를 **삭제**. 길 안내는 시스템 내비가 맡고, 앱은 일행 상태, 알림, 일정, 메세지 패널만 제공 |
| 2 | 앱 하나가 2560×1440 전체를 쓴다고 가정 (`ScaledStage`로 고정 해상도 스케일) | 고정 스케일을 걷어내고 **반응형 레이아웃**으로 전환. 세로 1창(기본, `screenOrientation` 미지정)을 우선 설계하고, 가로 2창 레이아웃을 별도로 설계 |
| 3 | `AndroidManifest`에 `screenOrientation="landscape"` 고정 | 기본은 세로 1창으로 두고, 가로 레이아웃은 창 크기(WindowSizeClass)에 따라 분기. 세로·가로 양쪽 디자인 산출물 필요 |
| 4 | Connect-S 17 / 14.6 / 12.9, Connect-W, WF 등 다중 디스플레이 고려 없음 | 디스플레이별 창 크기 대응 확인 (최소 창 폭 기준 레이아웃 검증) |
| 5 | 화면 가장자리 스와이프 등 제스처 사용 가능성 | 윈도우 바, 3손가락 스와이프는 **시스템 제스처**이므로 앱에서 쓰지 않음 (드래그 영역이 화면 가장자리에 닿지 않게) |

**재설계안(세로 1창 기준)**
- 상단: 현재 목적지 카드 (일정 n/N, 목적지명, 도착 예정 시각, **[다음 일정]** 버튼)
- 중단: 탭 (일행 차량 / 알림 / 일정), 게임 탭은 정차 중에만 노출
- 하단: 간편 메세지 칩
- 가로 2창일 때만 일행 차량 목록과 알림을 나란히 배치

### 1-2. 내비게이션 연동 (P0)
가이드: 하드웨어와 시스템 기능은 **SDK API로만 접근**. NaviHelper SDK(`ai.pleos.playground:NaviHelper:3.0.5`)는 별도 신청 없이 사용 가능.

| # | 현재 | 수정 |
|---|---|---|
| 1 | `TripViewModel.tick()`이 진행률을 시뮬레이션 | `NaviHelper.initialize()`, `addListener()`로 실제 경로 이벤트 수신. `onTripInfo`/`onDrivingInfo`(남은 시간·거리), `onDestinationArrived`(도착), `onWayPointArrived`(경유지 도착), `onRouteCancelled`, `onError`로 상태 갱신 |
| 2 | "다음 일정" 버튼이 내부 상태만 변경 | `requestRoute(RouteInfo(...))`로 시스템 내비에 다음 목적지 전달, 일행 차량에도 같은 RouteInfo를 서버를 거쳐 전파 |
| 3 | 정차 요청 수락 시 경유지를 자유롭게 추가 | `addWaypoint(RequestWaypointInfo)` / `requestRouteWithWaypoints`를 사용하고 **경유지 최대 2개**(`WaypointIndex.FIRST/SECOND`) 제한. 3번째 요청은 "경유지가 가득 찼어요" 안내 후 기존 경유지 교체 여부를 물음 |
| 4 | 권한 선언 없음 | `pleos.car.permission.NAVI_ROUTE`, `NAVI_ROUTE_SEARCH`를 Manifest에 선언 (커스텀 지도가 필요할 때만 `NAVI_CUSTOM_MAP`) |
| 5 | 의존성 없음 | `settings.gradle.kts`에 `maven("https://nexus-playground.pleos.ai/repository/maven-releases/")` 저장소, `app/build.gradle.kts`에 NaviHelper 의존성 추가 |
| 6 | 앱 종료 처리 없음 | `onDestroy`에서 `removeListener()`, `release()` 호출 |

### 1-3. 주행 중 제한, 운전자 주의 분산 (P0)
가이드: `CarUxRestrictionsManager.registerListener` → `onUxRestrictionsChanged`로 제한 상태를 받음. **DO(Distraction Optimized)를 선언하지 않은 앱은 주행 중 사용 불가**. 한국은 "그외 지역" 기준으로, 주행 중 키보드는 허용되지만 `NO_SETUP`, `NO_VIDEO`, QR 로그인, `LIMIT_CONTENT`/`LIMIT_STRING_LENGTH` 제한이 걸림. **주행 중 게임과 인터넷 브라우징 유도 금지**.

| # | 기능 | 주행 중 | 정차 중 | 수정 |
|---|---|---|---|---|
| 1 | 여행 생성, 일정 입력, 일정 분석 (PLAN 화면) | ❌ (`NO_SETUP`) | ✅ | 주행 중 진입 시 "정차 후 이용할 수 있어요" 안내 |
| 2 | QR로 폰 일정 불러오기, QR 초대 | ❌ (QR 금지) | ✅ | 사이드바 QR 버튼을 주행 중 비활성화하고 초대 코드만 표시 |
| 3 | 게임 (사다리, 뽑기) | ❌ | ✅ | 게임 탭을 주행 중 숨기거나 잠금. 동승자 웹에서 시작한 게임은 **결과 한 줄만** 알림 |
| 4 | 사다리 애니메이션 | ❌ | △ | 주행 중에는 애니메이션 없이 결과만 표시 |
| 5 | 일정 드래그 순서 변경 | ❌ (조작 복잡) | ✅ | 주행 중 드래그 핸들 비활성화. 변경은 호스트 동승자 모바일 웹이나 정차 중에만 |
| 6 | 정차 요청 수락/거절, 다음 일정 | ✅ | ✅ | 큰 버튼 2개 이하, 음성 응답 병행 |
| 7 | 간편 메세지 | ✅ (프리셋) | ✅ | 프리셋 칩만 허용, 자유 입력은 정차 중에만 |
| 8 | 알림 피드 긴 목록 | △ (`LIMIT_CONTENT`) | ✅ | 주행 중에는 최근 N개(예: 3개)만 표시, 스크롤 최소화 |
| 9 | 시연 패널 | ❌ | ❌ | 릴리스 빌드에서 제거 (`BuildConfig.DEBUG`에서만 노출) |

추가 작업
- Manifest의 Activity에 `<meta-data android:name="distractionOptimized" android:value="true"/>` 선언
- 주행/정차 상태를 `TripViewModel`에 노출(`isDriving`)하고 모든 화면에서 이 값으로 분기
- `LIMIT_STRING_LENGTH`가 걸리면 긴 문구(주소, 메세지 본문)를 잘라 표시

### 1-4. 앱 카테고리 (P1)
- 카테고리 후보: **Mobility Services**(경유지 설정 허용) 또는 Social/Communication
- 핵심 기능이 "경유지/목적지 동기화"이므로 **Mobility Services로 신청**하고, 게임은 부가 기능(정차 중 전용)으로 정리

### 1-5. 생명주기, 포그라운드/백그라운드 (P1)
가이드: 앱은 포그라운드와 백그라운드를 자주 오가므로 **복귀 시 상태를 복원**하고, **백그라운드에서는 애니메이션과 타이머를 중지**.

| # | 현재 | 수정 |
|---|---|---|
| 1 | `DriveScreen`의 `withFrameNanos` 루프가 계속 돎 | 시뮬레이션 루프 제거. NaviHelper 콜백과 서버 이벤트만으로 갱신 |
| 2 | `later()` 타이머, 시계 갱신 코루틴이 백그라운드에서도 동작 | `repeatOnLifecycle(STARTED)` 안에서만 실행 |
| 3 | 프로세스가 종료되면 여행 상태 소실 | `SavedStateHandle`과 로컬 저장소(DataStore/Room)에 여행 ID, 현재 구간, 피드를 저장하고 재시작 시 복원 |
| 4 | 무한 반복 애니메이션 (다음 버튼 펄스, 음성 파형, 로고 회전) | 백그라운드 중지는 물론, 디자인 가이드에 따라 대부분 제거 (2-1 참고) |

### 1-6. 성능 (P1)
가이드: 내비가 아닌 앱은 **주행 중 CPU 5% 미만**, 정차 중 25% 이하, **RAM 400MB 이하**, 빠른 콜드 스타트(지연 로딩), 백그라운드 타이머와 폴링 최소화, 오디오 포커스 정책 준수.

- 지도 Canvas를 제거해 매 프레임 그리기 비용 없앰
- 일행 위치 갱신은 서버 푸시(WebSocket/FCM)로 받고, 폴링이 필요하면 주기를 늘림(예: 10초 이상)
- 화면별 지연 로딩, 게임 모듈은 첫 진입 시 로드
- 음성 안내(TTS)를 쓰면 `AudioFocusRequest`(`AUDIOFOCUS_GAIN_TRANSIENT_MAY_DUCK`)로 내비 음성과 충돌 방지
- 측정: Android Studio Profiler로 주행 시나리오 CPU와 메모리 기록 후 제출

### 1-7. 네트워크 단절 대비 (P1)
- 터널, 산간 구간을 가정해 **마지막 일정, 일행 위치 캐시** 표시 ("3분 전 위치")
- 메세지와 정차 요청은 **전송 대기 큐**에 넣고 재시도, 타임아웃 처리
- 오프라인 배너: "연결이 끊겨 최근 정보로 보여드려요"
- 일정 변경 충돌(두 사람이 동시에 순서 변경) 시 호스트 우선 규칙 명시

### 1-8. 보안, 개인정보 (P0)
가이드: 계정 전환과 로그아웃이 쉬워야 하고, 토큰은 Keystore에 보관. 개인정보는 최소로 수집하고 목적을 명시(위치)하며 동의 흐름은 간단하게. 로그 마스킹, 차량/사용자 ID 익명화, 주행 데이터의 마케팅 활용 금지.

| # | 수정 |
|---|---|
| 1 | 여행 참여 시 **"여행 중에만 일행에게 내 차 위치를 공유해요"** 동의 화면 추가 (정차 중, 버튼 2개) |
| 2 | 여행 종료 시 위치 공유 자동 종료, 종료 안내 |
| 3 | 화면에 표시하는 이름은 닉네임만, 서버 전송 시 차량 ID와 사용자 ID는 해시 처리 |

가이드: 1~2초 안에 이해. 응답은 0.25초 이내, 아니면 로딩 표시. 대비 4.5:1 이상. 텍스트는 영문 기준 120자 / 24단어 이하, 한 줄 80자 이하, 최대 3줄. 중요 텍스트 높이 5mm 이상, 보조 3mm 이상, 최소 12sp.

| # | 현재 | 수정 |
|---|---|---|
| 1 | 정차 요청 배너에 "요청자 · 사유 · 거리 · 추가 시간"까지 긴 문장 | 제목 1줄("서연님이 휴게소 정차 요청") + 정보 1줄("+8분") + 버튼 2개로 축소 |
| 2 | 모달 설명 문구 2~3문장 | 1문장, 3줄 이내로 축소 |
| 3 | 일정 탭 안내 문구("다음 일정은 드래그해서…동기화돼요") | 주행 중 숨김, 정차 중에도 1줄로 |
| 4 | 회색 보조 텍스트(`G.mute` #6B7280 계열)가 어두운 배경에서 대비 부족 가능 | 모든 텍스트/배경 쌍의 대비를 측정해 **4.5:1 미만은 색 조정** |
| 5 | 일부 22~24px 텍스트 | 160dpi 12.8" 기준 mm 환산 후 **중요 정보 5mm 이상** 확보 (ETA, 목적지명, 버튼) |
| 6 | 일정 분석, 참여 처리 등 비동기 작업 | 0.25초를 넘으면 로딩 상태 표시 |
| 7 | 아이콘만 있는 버튼 (지도 확대/축소, QR, 드래그 핸들) | **아이콘에 텍스트 라벨** 추가 (지도 버튼은 지도 제거로 삭제) |

### 2-4. 알림 (P0)
가이드: 꼭 필요한 알림만, 광고 금지. **System Notification**(App icon / Profile / Image / Action, 버튼 Single / Vertical / Horizontal)과 **Toast** 컴포넌트 사용.

- 음성 입력 시뮬레이션(`simulateVoice`)을 **Gleo AI 음성 연동**으로 교체: "응/수락", "아니/거절", "다음 일정", "늦는다고 보내줘"

### 2-6. 주야간 모드, 다국어 (P1)

## 3. 기획 내용 변경 필요 사항 (기획서 반영)

| 기획서 항목 | 변경 |
|---|---|
| 호스트 일정이 일행 차량 **내비에 자동 등록** | NaviHelper `requestRoute`로 구현 가능. 단, **다른 차량에는 바로 경로를 바꾸지 않고 "다음 목적지로 안내할까요?" 확인 후 적용** (운전자 동의) |
| 정차 요청 → 경유지 추가 | **최대 2개** 제약 반영. 요청 사유는 프리셋(화장실, 휴게소, 주유, 식사) |
| 일정 드래그 순서 변경 | **정차 중 또는 동승자 모바일 웹 전용**으로 변경 |
| 차량별 위치/ETA 사이드바 | 지도 없이 **리스트와 진행 바**로만 표현 (현재 설계 유지, 지도 제거) |
| 간편 메세지 | 프리셋만 유지, 자유 입력은 정차 중에만 |
| 간단한 게임 | **정차 중(휴게소)** 기능으로 재정의. 주행 중에는 동승자 웹에서만 진행하고 차량 화면은 결과만 |
| QR 일정 불러오기, 초대 | 정차 중 전용, 주행 중에는 코드만 |
| 여행 요약 | 유지 (정차 후 표시) |
